# Starter Project 개발 로드맵

비율은 단계 완료 시의 예상 누적 작업 범위이며 시간 비율이 아니다.

| 단계 | 범위 | 완료 기준 | 목표 비율 |
| --- | --- | --- | --- |
| 1 | 초기 설계 확정 | 공통/게임 경계, 데이터, 플랫폼·UI, 수명·실패 정책 결정 | 5% |
| 2 | Bootstrap → Title → Main | 초기화 상태, 중복 방지, 공통 루트 유지, 실패 시 진입 차단 | 30% |
| 3 | 기본 설정·사용자 설정 | SO 기본값과 사용자 JSON의 적용·저장·재실행 복원 | 45% |
| 4 | 게임 시작·저장 기반 | 새 게임·이어하기, 파일 버전·백업·복구·쓰기 실패 처리 | 65% |
| 5 | 최소 공통 기능 연결 | 오디오·입력·로딩·화면 설정과 사용자 설정 연결 | 75% |
| 6 | 개발 편의·설정 검증 | Main 직접 Play 시 Boot 경유, 설정 검사·테스트 데이터 초기화 | 85% |
| 7 | 통합 테스트·실제 빌드 | 정상·오류 흐름을 Editor와 대상 플랫폼 빌드에서 검증 | 95% |
| 8 | 템플릿 정리·배포 | 식별 정보 정리, 깨끗한 복제 검증, 문서·커밋·템플릿·태그 | 100% |

2026-09-10: 1~4단계를 구현했고 EditMode 30개·PlayMode 14개 테스트가 통과했다. 로드맵 범위 기준 약 65%에 해당한다. SO 기본값·사용자 JSON 저장·복원, 새 게임·이어하기, 파일 버전·백업·복구·쓰기 실패 처리를 포함한다.
2026-09-22: 5단계 음량·화면 설정 적용, UI 입력·선택 복원, 씬 전환 로딩 표시를 연결했고 EditMode 44개·PlayMode 25개가 통과했다. 상세 검증 결과와 실제 기기 확인 범위는 [공통 기능 가이드](COMMON_SERVICES.md)에 기록한다. 로드맵 범위 기준 약 75%이며 다음은 6단계의 Main 직접 Play 경로, 설정 검사·테스트 데이터 초기화 도구다.
상세 사용법은 [Bootstrap 사용 가이드](BOOTSTRAP.md)와 [설정·게임 저장 가이드](SETTINGS_AND_SAVE.md)를 따른다.
2026-09-23: 6단계 착수 전 [로그라이크·로그라이트 사전 조사](ROGUELIKE_PLAY_FLOW_RESEARCH.md)를 작성했다. 실제 게임 6종의 공개 사례를 비교하고, 격리된 새 테스트 세션을 기본으로 하는 Main 직접 Play와 저장 복사본 재현 경로를 제안했다. 설계 제안이며 6단계 구현 완료나 게임별 저장 정책 확정을 의미하지 않는다. 현재 범위는 약 75%를 유지한다.
2026-09-23: 범용성 검토 후 장르별 사망·성장·자동 저장 규칙을 공통 기반에서 제외하고, 6단계 Main 직접 Play·설정 검사·테스트 데이터 백업 도구를 구현했다. Unity 6000.3.16f1 복제본에서 EditMode 46개·PlayMode 26개가 모두 통과했다. 일회성 Editor 자동 검증은 도메인 재로드 켜짐·꺼짐에서 각각 Main 직접 Play 두 번, Boot 경유, 별도 저장소, 시작 씬 복원과 일반 저장 보호를 확인했다. 미저장 Main 씬 보호는 재로드 꺼짐에서 확인했다. 다만 자동 검증을 위해 복제본에서만 batchmode 차단 조건을 해제했으며 GUI 직접 조작·테스트 데이터 메뉴 대화상자는 아직 확인하지 않았다. 코드·자동 검증 기준 6단계까지 약 85%이며, 이 현장 확인과 전체 앱·빌드 검증은 7단계에서 이어간다. 상세 결과는 [Editor 작업 가이드](EDITOR_WORKFLOW.md)를 따른다.
2026-09-23: 7단계 Windows x64 개발 빌드를 생성하고, 별도 빌드 프로세스에서 첫 실행·설정/게임 저장·재실행 복원·이어하기와 파손/미래 버전 파일 보호를 자동 확인했다. 파손된 주 파일의 명시적 백업 복구·손상 원본 보존도 새 프로세스에서 확인하고 Direct3D 11 장치 경로를 실행했다. 저장 완료 직후 강제 종료·재실행과, 계측 복제본의 임시 파일 flush 후 주 파일 교체 전 강제 종료·재실행에서도 이전 정상 저장으로 이어하기가 됐다. 후자는 미완료 `.tmp`를 남기며 다른 중단 시점·전원 손실까지 증명하지 않는다. GUI 직접 조작·오디오·물리 입력 확인이 남아 있어 7단계 완료 및 95% 반영은 보류한다. 범위와 결과는 [통합·빌드 검증 기록](INTEGRATION_VALIDATION.md)을 따른다.
2026-09-23: [SOLID·패턴 점검](ARCHITECTURE_REVIEW.md)에서 기존 구성의 책임·의존 경계를 검토했다. 플랫폼 설정 적용 실패 후 새 JSON이 남는 경계를 수정했고 EditMode 46개·PlayMode 27개를 통과했다. 변경된 Core의 Windows 개발 빌드에서 별도 프로세스 첫 저장·재실행 이어하기를 확인했다. 7단계 GUI·장치 현장 확인은 계속 남아 있어 완료 비율을 올리지 않는다.
2026-09-23: Boot 씬의 상태 표시·입력 연결을 `Validate Setup`에서 검사하도록 보완하고 EditMode 46개·PlayMode 27개 전체 통과, 새 Windows 개발 빌드의 별도 프로세스 저장·재실행 이어하기를 확인했다. 숨겨진 Player 화면 캡처는 검은 화면이라 GUI 시각 검증은 여전히 남는다. 완성된 프리셋을 새 게임에 인계할 기준은 [상세 Summary](PRESET_SUMMARY.md)에 기록했다.
테스트는 기능 구현과 함께 진행하며, 7단계에서는 전체 연결을 검증한다.
