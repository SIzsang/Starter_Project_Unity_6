## 목표

Unity 프로젝트마다 반복하는 실행·초기화·저장·씬·입력·설정 기반을 표준화합니다. 작은 게임은 필요한 부분만 사용하고 규모가 커져도 같은 Core 계약 위에서 확장합니다.

## 현재 단계

| 단계 | 범위 | 상태 |
| --- | --- | --- |
| Phase 1 | 실행 골격·저장·설정·예제 UI·인계 | 구현·기존 v1.0.0 배포 완료. 후속 3슬롯·메뉴 보완 포함 |
| Phase 2 | 실행 상태·씬 수명·서비스·Runtime·입력·Pause·Audio | 10개 작업과 Gate 완료 |
| Phase 3 | Logging·Debug·빌드·Validator·Smoke | 5개 작업과 Gate 완료 |
| Phase 4 | 선택형 공통 모듈 | 사용자 선정 Pool 범위와 Gate 완료. 다른 후보 보류 |

현재 프리셋으로 Windows·URP 2D 게임 제작을 시작할 수 있습니다. 전체 프리셋을 하나의 완료율로 표시하지 않습니다. [현재 사용 판정](PRESET_SUMMARY.md)

## 후속 순서

| 순서 | 작업 | 상태·완료 기준 |
| --- | --- | --- |
| 1 | 소스·문서 기준 정리 | 완료. 작업별 커밋, 메타 추적, 현재 안내와 과거 기록 구분 |
| 2 | 작은 Game Layer 적용 사례 | 다음 권장 Work. 새 게임 → 플레이 → 저장 → Title/Continue → 씬 종료 |
| 3 | 필요한 Player·개발 도구 확인 | 적용·인계 시 선택한 환경의 실제 사용 경로만 확인 |
| 4 | 새 소스 버전·인계 | 실제 사용 소스·안내·검증 범위 일치. 새 Release는 별도 배포 작업 |

상세 범위와 완료 조건은 [후속 계획](NEXT_STEPS.md)을 따릅니다. 새 Phase 이름·게임 장르·추가 플랫폼은 아직 확정하지 않았습니다.

## 선택 모듈을 추가하는 기준

Pool은 선택 사용할 수 있습니다. 나머지는 실제 다국어 콘텐츠, 중첩 팝업, 사용자 키 저장, 비동기/원격 콘텐츠, 여러 시간 영역, 추가 플랫폼 SDK의 요구가 생겼을 때 선정합니다. 후보 목록을 고정 구현 순서로 해석하지 않습니다.

전투·인벤토리·퀘스트·AI·성장·스테이지 규칙은 Game Layer에 둡니다. 반복 사용이 확인되면 별도 Gameplay Module로 검토합니다.
